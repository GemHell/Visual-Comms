Creating Reusable UI Elements

The Speech Bubble Example

Today we're building a simple speech bubble but you can use all the principles we cover to create other reusable UI elements.

To get there, we'll cover:

  • CSS selectors
  • The div element
  • The box model
  • Positioning
  • Z-index

The speech bubble pulls all of them together in a single, reusable class.

The <div> Element

A <div> is a generic, block-level container. It has no visual appearance of its own: no color, no border, no size. Its job is to wrap content so you can target and style it as a unit with CSS.

Our speech bubble starts as a bare div with text inside:

<div>I've never seen this path before...</div>

Right now it looks like plain text. To style it, we need a way to target it in CSS, which means giving it a class.

<div class="speech-bubble">I've never seen this path before...</div>

Now CSS can find it. The class is the hook that connects the HTML to the stylesheet.

CSS Selectors: Type, Class, and ID

CSS selectors tell the browser which HTML elements to style. There are three fundamental types.

Type Selectors

A type selector targets every element of a given tag. A rule for div applies to every div on the page, useful for broad defaults but too broad for a specific element like our bubble.

/* Styles every <div> on the page */
div {
    font-size: 60px;
}

Class Selectors

A class selector targets any element with a matching class attribute. In CSS, class names are preceded by a period . — this is how we'll style the speech bubble. Write the rule once, apply it to as many divs as you need.

/* targets any element with class="speech-bubble" */
.speech-bubble {
    background-color: rgb(194, 194, 255);
    border-radius: 60px;
    padding: 12px 16px;
}

In your HTML:

<div class="speech-bubble">I've never seen this path before...</div>
<div class="speech-bubble">We should turn back.</div>

ID Selectors

An ID selector targets one unique element. IDs are preceded by # and should only appear once per page. Use them for page-specific overrides. For example, positioning a bubble differently on one particular scene.

/* targets only the bubble on scene 3 */
#scene-3-bubble {
    top: 40px;
    left: 60px;
}

Quick Reference

Selector Syntax Targets
Type div { } All <div> elements
Class .speech-bubble { } Any element with class="speech-bubble"
ID #scene-3-bubble { } The one element with id="scene-3-bubble"

Side note: the :hover pseudo-class: We covered this in an earlier week, but it fits here as well. The :hover pseudo-class (e.g. .speech-bubble:hover { opacity: 0.8; }) applies styles only when the user's cursor is over an element. You can append :hover to any type, class, or ID selector. It's just another way of targeting elements, this time based on user interaction rather than structure.

The Box Model

Every HTML element, including our speech bubble div, is treated by the browser as a rectangular box. The CSS Box Model describes the layers that make up that box, from the inside out:

  • Content: the text inside the bubble
  • Padding: space between the text and the bubble's edge (inside the border)
  • Border: the visible outline around the bubble
  • Margin: space outside the border, separating the bubble from neighboring elements
.speech-bubble {
    padding: 12px 16px;          /* space between text and border */
    border: 6px solid #333333;   /* visible outline */
    border-radius: 60px;          /* rounds corners into bubble shape */
    margin: 10px;                 /* space outside the bubble */
}

You can play around with these properties in this interactive box model demo at w3schools.com: CSS Box Model.

Positioning Elements with CSS

The CSS position property controls how an element is placed in the document. To float our speech bubble over a scene image, we need to understand two key values: relative and absolute.

The Five Position Values

static (default)

Every element is static by default. It flows in normal document order and ignores top, left, right, and bottom.

relative

The element stays in normal flow but can be nudged from its original position. We use this on the scene container to establish it as the reference point for the bubble.

.image-container {
    position: relative; /* makes this the anchor for absolutely-positioned children */
}

absolute

The element is removed from normal flow and positioned relative to its nearest positioned ancestor. This is how we place the speech bubble at a specific spot over the image.

.speech-bubble {
    position: absolute;
    top: 20px;  /* 20px from the top of .image-container */
    left: 20px; /* 20px from the left of .image-container */
}

fixed

Positioned relative to the browser window, stays in place while scrolling. Useful for persistent UI like a navigation bar or a status bar in your story.

.status-bar {
    position: fixed;
    top: 0;
    width: 100%;
}

sticky

A hybrid of relative and fixed. Scrolls with the page until it hits the specified offset, then locks in place.

.chapter-title {
    position: sticky;
    top: 0;
}

Z-Index

When elements overlap, the browser needs to know which one sits on top. The z-index property controls this stacking order. Think of it as layers: a higher number means closer to the viewer.

Important: z-index only works on elements that have a position value other than static.

.scene-image {
    position: relative;
    z-index: 1; /* image sits behind */
}

.speech-bubble {
    position: absolute;
    z-index: 2; /* bubble sits in front of the image */
}

For more on how z-index layers work: How Does Z-Index Layer Work? (GeeksforGeeks)

Placing Text Over an Image

Now we can put it together. The scene container wraps both the image and the speech bubble. With position: relative on the container, the bubble can be placed anywhere over the image using z-index to ensure it sits on top.

.image-container {
    position: relative; /* reference point for the bubble */
}

.image-container img {
    position: relative;
    z-index: 1; /* image on layer 1 */
    width: 100%;
}

.speech-bubble {
    position: absolute;
    z-index: 2; /* bubble on layer 2, in front of the image */
    top: 20px;
    left: 20px;
}

In your HTML:

<div class="image-container">
    <img src="images/scene.jpg" alt="A forest path at night">
    <div class="speech-bubble">I've never seen this path before...</div>
</div>

For a full walkthrough: How to Place Text Over an Image Using CSS (GeeksforGeeks)

Creating the Speech Bubble

Now to combine the div, the class selector, the box model, positioning, and z-index, all together.

The HTML

Create the<div> with the "speech-bubble" class.

<div class="image-container">
    <img src="images/scene.jpg" alt="A forest path at night">
    <div class="speech-bubble">I've never seen this path before...</div>
</div>

The CSS

Combining everything together as one class (with a few extra adjustments) gives every bubble across all your story pages the same look:

.speech-bubble {                            /* class selector: write once, reuse on every page in your story */
    position: relative;                   /* lifts the bubble out of normal flow for precise placement */
    top: 20px;
    left: 20px;
    z-index: 2;                           /* renders in front of the scene image (image is z-index: 1) */
    background-color: rgb(194, 194, 255);
    color: #111111;
    padding: 12px 16px;                  /* space between text and bubble edge so it doesn't look cramped */
    border: 6px solid #333333;
    border-radius: 60px;                 /* softens corners into the rounded bubble shape */
    margin: 10px;                        /* space outside the bubble, separates it from neighboring elements */
    max-width: 600px;			/* prevents the bubble from getting too wide on larger screens */
    font-size: 60px;
    line-height: 1.4;
}

You can extend this same pattern for navigation choices (.choice-link), character name labels (.character-name), or any repeating UI element across your story pages. As noted in Week 11, you can also create clickable hotspot areas directly on images using HTML Image Map: another way to embed navigation within a scene.

Reusable Class Ideas for Your Interactive Story

As you build your story, think about which elements repeat across pages. Each one is a candidate for a reusable class. Define it once in your stylesheet and apply it wherever you need it.

  • Speech bubble (.speech-bubble) — character dialogue overlaid on a scene image
  • Choice links (.choice-link) — styled navigation buttons that move the reader between pages
  • Character name label (.character-name) — a small tag identifying who is speaking or present
  • Place name label (.place-name) — overlaid location title for each scene
  • Narration box (.narration) — a semi-transparent panel for story text that isn't dialogue
  • Back / forward navigation (.nav-arrow) — consistent previous/next controls across all pages

You do not need all of these. Just pick the ones that fit your story. The key idea is to create a class any time you catch yourself writing the same styles twice.
